# 2026世界杯球队信息系统需求文档

## 1. 文档内容

本文档确定课程项目的业务范围、用户权限、功能、数据约束、部署目标和验收标准，作为后续设计、实现及验收的依据。

## 2. 项目概述

### 2.1 定位与目标

建设中文体育资讯风格的数据库网站，围绕2026世界杯精选球队，集中展示球队、球员、教练、比赛和荣誉。访客可浏览信息、比较球队、查看统计图表并提交留言；管理员在后台统一维护内容。

### 2.2 已有项目基础

当前代码基于 Yii2 Advanced 模板。需求与目录的对应关系如下：

| 目录 | 计划职责 |
| --- | --- |
| `advanced/frontend` | 公开浏览页面、球队对比、留言提交与展示 |
| `advanced/backend` | 管理员登录及业务数据维护 |
| `advanced/common` | 共享业务模型、校验规则及公共配置 |
| `advanced/console` | 数据初始化及维护命令 |
| `文档` | 课程需求、设计、实现、用户手册、部署与演示资料 |

## 3. 用户与权限

| 用户 | 权限 |
| --- | --- |
| 访客 | 无需注册登录，可浏览公开内容、查询筛选、对比球队、查看图表和提交留言 |
| 管理员 | 登录后台，统一维护全部业务数据、审核留言及管理内容发布状态 |

前台不提供普通用户注册、登录和个人中心。不设置成员、编辑等分级后台角色。后台页面和写入接口均须验证管理员身份，访客不得直接调用后台接口修改数据。

## 4. 前台功能需求

### FR-01 首页与导航

首页展示网站主题、精选球队入口、近期或最近录入的比赛。导航可到达球队、球员、比赛、球队对比等主要页面。全站使用中文界面，专业名称可保留原文。

### FR-02 球队信息

- 提供球队列表和详情，可按球队名称查询。
- 展示球队名称、所属国家或地区、简介、教练、球员阵容和荣誉。
- 关联展示本站已录入的相关赛程、比赛结果及球队战绩。
- 球队详情提供留言入口及已审核留言。

### FR-03 球员与教练信息

- 球员列表支持按姓名和所属球队查询，可按位置筛选。
- 球员详情展示姓名、照片、国籍、出生日期等基本资料，以及所属球队、号码和比赛统计。
- 球员比赛统计以出场、进球为基础，不扩展到生涯、转会或完整历届赛事数据。
- 教练展示姓名、照片、国籍、简介及执教球队，可从球队详情访问。
- 球员详情提供留言入口及已审核留言。

### FR-04 赛程、比分与比赛详情

- 比赛列表支持按球队、日期、比赛阶段和状态筛选。
- 比赛详情展示时间、场地、双方球队、比分。
- 比分由管理员手动更新，不提供实时推送。
- 未录入的比分显示为“未公布”等明确状态，不得默认解释为0:0。
- 可从比赛页面访问双方球队详情，并提交、查看审核通过的比赛留言。
- 仅收录部分比赛，不提供完整小组积分榜、淘汰赛对阵或晋级推演。
- 不提供事件时间轴、首发替补阵容、文字直播及控球率、射门等详细技术统计。

### FR-05 球队对比

访客选择两支不同球队，页面并列展示球队基本资料及进球、失球数据，并明确说明统计仅覆盖本站已录入的2026世界杯已结束比赛。选择同一球队或数据不足时给出提示。不得将样本统计表述为完整世界杯数据。

### FR-06 动态图表

提供球队胜、平、负占比饼图。切换球队后，图表根据数据库中的有效比赛重新生成，并显示各项场次及统计范围。无有效比赛时展示空状态，不绘制虚假的占比。不增加球员排行榜或其他未确认图表。

### FR-07 球队荣誉

在球队页面展示荣誉名称、赛事、年份和说明。历史荣誉与2026世界杯比赛统计分开呈现，历史成绩不计入本届赛事战绩。

### FR-08 留言与审核

- 访客填写昵称和正文，可针对球队、球员或比赛留言，不要求注册。
- 提交成功后留言进入待审核状态，前台提示“审核通过后显示”。
- 前台仅展示审核通过的留言；待审核、未通过和已删除留言不可公开访问。
- 管理员可查看留言对象、内容和提交时间，执行审核通过、审核不通过或删除。
- 基础规则：昵称1—30字、正文1—1000字，均须去除首尾空白后校验；空白内容不能提交。
- 留言内容按普通文本安全展示，限制连续重复提交。不增加楼中楼、点赞或私信。

## 5. 后台功能需求

### FR-09 管理员登录

提供登录、退出和会话验证，密码须以安全散列形式保存。登录失败给予合理提示，所有写操作执行身份校验和请求校验。初始管理员通过部署初始化流程创建，部署说明应给出首次登录及修改初始密码的方法。

### FR-10 数据维护

管理员可维护球队、球员、球队阵容关系、教练及执教关系、比赛、球员比赛统计、荣誉及球队荣誉记录。维护页面应提供列表、查询、详情、新增和编辑能力，并对必要字段和关联关系进行校验。

删除具有比赛、阵容等关联记录的数据时，应阻止直接删除并提示依赖关系，或采用设计阶段明确的停用方案；不得静默级联删除历史比赛。

### FR-11 媒体与统计维护

后台支持维护队徽、球员和教练照片。上传时验证文件类型和大小，使用安全文件名并禁止执行上传内容；没有图片时提供占位展示。具体图片格式、大小上限和存储路径在设计阶段确定。

比赛记录更新后，相关战绩、对比和图表应在后续访问时反映最新数据。球员统计可手动维护。

## 6. 数据范围与业务规则

### 6.1 录入与来源

首批6支球队及部分比赛由网络真实数据收集，管理员手动整理。球队、球员和比赛资料应记录来源或出处，便于核对；不在本文预先指定参赛名单、阵容或比赛结果。资料缺失时保留空值或说明，不能以0或虚构内容替代未知数据。

比赛的双方均须存在球队记录。若精选球队的比赛涉及库外对手，则仅保留库外球队名称以便展示比赛比分情况，其他具体内容不进行录入；初始6支为重点展示对象，不要求补录对手的球员资料。

### 6.2 比赛与战绩口径

- 一场比赛必须关联两支不同球队；比分为非负整数，允许未确定比分为空。
- 比赛时间统一按北京时间显示，仅显示日期不显示具体时间；日期筛选使用同一口径。
- 仅录入已结束比赛的比分。
- 每场比赛对每队只计一次；进球等于该队比分，失球等于对方比分。
- 胜平负按比赛结束时的比分判断，含加时赛，不含点球大战罚球数；点球决胜的平局在本系统统计中仍记为平局。
- 未开始、进行中、延期、取消及比分不完整的比赛不计入统计。
- 同一比赛、同一球员仅有一条统计记录；球员须属于该场比赛某一参赛球队。
- 球员统计来自手动维护的球员比赛记录，展示范围应明确，不声称覆盖其全部赛事或生涯。

## 7. 数据实体与数据库规模

最终表名、字段、键、约束和数据库字典在设计文档确定，不通过无业务意义的拆表凑数量。

| 序号 | 候选实体 | 用途 |
| --- | --- | --- |
| 1 | 管理员 | 后台身份与认证 |
| 2 | 球队 | 国家或地区、队徽及简介 |
| 3 | 球员 | 基本资料 |
| 4 | 球队球员关系 | 本届赛事阵容、号码和位置 |
| 5 | 教练 | 教练基本资料 |
| 6 | 球队教练关系 | 本届赛事执教关系 |
| 7 | 比赛场地 | 场地名称和位置资料 |
| 8 | 比赛 | 对阵、时间、阶段、比分 |
| 9 | 球员比赛统计 | 出场、进球、助攻等统计 |
| 10 | 荣誉 | 荣誉或赛事奖项定义 |
| 11 | 球队荣誉记录 | 球队获得荣誉的年份和说明 |
| 12 | 留言 | 昵称、正文、留言对象及审核状态 |

留言每条只关联一个球队、球员或比赛对象，具体约束方案在设计阶段确定。最终验收需检查实际业务表数量大于10。

## 8. 界面与非功能需求

| 类别 | 要求 |
| --- | --- |
| 界面 | 中文体育资讯风格，电脑端优先，列表、详情、筛选和返回路径保持一致 |
| 适配 | 以常见桌面浏览器和桌面宽度为验收重点；手机端不作为完整适配承诺 |
| 可用性 | 表单提示明确；空数据、加载失败、记录不存在时提供可理解的反馈 |
| 安全 | 防止未授权后台访问、SQL注入、留言脚本注入、伪造写请求及危险文件上传 |
| 一致性 | 使用数据库关联约束或等效业务校验，多记录修改时保证一致性 |
| 性能 | 列表分页、查询合理使用索引；在课程演示数据规模下无明显操作阻塞 |
| 可维护性 | 遵守MVC、统一命名、PHP文件注释头要求，配置与敏感信息分离 |
| 可恢复性 | 提供数据库初始化SQL及部署还原步骤，初始化不得静默覆盖已有业务数据 |

## 9. Windows部署与初始化

### FR-12 一键初始化

目标环境为 Windows 本机已具备兼容的 PHP、MySQL 和 Composer。具体兼容版本在实现时验证并记入部署文档。

通过批处理或 PowerShell 入口简化项目初始化，至少应完成：

1. 检查PHP、数据库、依赖工具及必要扩展。
2. 安装或检查项目依赖，初始化Yii2环境。
3. 按用户提供的配置连接MySQL并导入初始化SQL。
4. 创建初始管理员，配置运行所需目录。
5. 输出前后台启动方式、访问地址和初始化结果。

脚本需在失败时给出原因及后续处理建议。重复执行不得无提示清空数据库；数据库已存在时应停止覆盖并提示处理方式。脚本不负责自动安装PHP、MySQL等系统软件，也不要求自动部署到公网服务器。

数据库导出文件放置于仓库的 `data/install.sql`，相对本需求文档所属项目工作目录为 `../install.sql`。具体脚本名称和启动方式在部署设计时确定。

## 10. 主要业务流程

### 10.1 浏览信息

访客进入首页 → 访问列表并查询或筛选 → 进入球队、球员或比赛详情 → 查看关联资料、统计与已审核留言。

### 10.2 提交留言

访客进入目标详情 → 填写昵称和正文 → 校验通过后保存为待审核 → 管理员审核 → 通过后在对应详情公开展示，未通过则不公开。

### 10.3 比赛维护与统计

管理员登录 → 选择双方球队、场地并录入比赛 → 更新状态和比分 → 校验并保存 → 符合统计条件的比赛进入球队战绩、两队对比和胜平负图表。

## 11. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 初始数据 | 有6支重点展示球队，含可核对的资料、阵容、教练、部分真实比赛及来源记录 |
| AC-02 | 球队与球员 | 列表查询、详情及关联跳转有效；资料缺失有合理提示 |
| AC-03 | 比赛 | 筛选有效；详情包含已确认字段；未知比分不显示为默认0:0 |
| AC-04 | 对比 | 可比较两支不同球队，进失球与有效比赛记录一致，统计范围可见 |
| AC-05 | 图表 | 切换球队后饼图正确变化；无比赛显示空状态；未结束比赛不计入 |
| AC-06 | 留言 | 未审核留言前台不可见，通过后在正确对象下可见，未通过或删除后不可见 |
| AC-07 | 荣誉 | 荣誉关联正确且不影响本届赛事战绩 |
| AC-08 | 权限 | 未登录无法访问后台或执行写接口；管理员可维护业务数据并退出 |
| AC-09 | 数据校验 | 阻止同队对阵、负数比分、空白留言及破坏关联的直接删除 |
| AC-10 | 数据库 | 实际业务表超过10张，初始化SQL能还原结构和演示数据 |
| AC-11 | 部署 | 在约定Windows环境按脚本及说明完成初始化并访问前后台；失败与重复初始化有明确提示 |
| AC-12 | 代码与交付 | 命名、PHP注释头、MVC成员贡献及课程资料能按要求核对；用户决定省略项单独记录 |

数据准备时须确定能覆盖上述主要验收场景的样本。

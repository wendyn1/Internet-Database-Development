# 2026世界杯球队信息系统实现文档

## 1. 文档内容

本文档记录系统各功能模块的实现结果，包括文件构成、关键实现方式与验证证据，作为设计文档所定方案的落地说明与验收对照材料。

系统基于 Yii2 Advanced 模板与 MySQL 实现，代码位于 `data/team/advanced`，全部业务表结构与样本数据收录于 `data/install.sql`。功能按三个业务模块组织开发：比赛与统计模块（第 2—6 章）覆盖比赛维护、库外对手、战绩聚合、两队对比与统计图表；认证与留言模块（第 7—10 章）覆盖管理员登录、留言提交与后台审核；基础资料模块（第 11—14 章）覆盖球队、球员、阵容、教练与荣誉的展示与维护。三个模块分别由组员二、组长、组员一负责实现，每人独立完成本人模块的模型、控制器与视图；文档末章记录模块间的交叉审阅结论。

各模块功能范围的编号沿用设计文档《B、C 编码交接清单》中的 C1—C8 与 B1—B8，便于与交接过程及验证记录对照；认证与留言模块在交接清单中未编号，本文以 A1—A6 自定义编号，仅在本章与第 7 章间对照使用。

## 4. 比赛与统计模块关键实现说明

### 4.1 比赛状态与比分

- 状态为 `finished` 时，双方比分必须同时为非负整数；其他状态双方比分必须为 `NULL`，避免“未结束却有比分”的脏数据。
- 比分含加时、不含点球大战；点球决胜按平局计入统计。
- 库外对手通过 `home_team_id`/`away_team_id` 为 `NULL`、同时保留展示名称实现；至少一侧必须关联本库球队，两侧不能相同。

### 4.2 统计存在时的字段锁定

`FootballMatch::LOCKED_ATTRIBUTES` 包含赛事年份、双方球队 ID 与名称、状态、双方比分。模型在保存前查询该场是否存在球员统计，存在则比较原值与新值，任何锁定字段变化都会产生校验错误。后台表单同时将这些控件置灰，形成“界面提示 + 服务端强制”的双重约束。解锁只能通过删除该场全部统计完成，不能通过自动删除统计实现。

### 4.3 球员统计校验

- 只能关联 `finished` 比赛；
- 阵容记录的 `tournament_year` 必须等于比赛年份；
- 阵容所属球队必须是本场主队或客队；
- 进球数不得超过本队本场比分；
- `appeared = 0` 时进球必须为 0，已知助攻也必须为 0；
- 助攻为 `NULL` 表示“未核实”，前台显示“未核实”，不按 0 处理；
- `match_id + team_player_id` 唯一，防止同场重复统计。

### 4.4 统计服务

`TeamStatsService::getSummary($teamId, $year = 2026)` 使用一条聚合 SQL：

- 只取 `status = 'finished'` 且双方比分非 `NULL` 的比赛；
- 每场比赛对指定球队只计一次，不 JOIN 球员统计表，避免一场重复计数；
- 胜平负按本队进球与失球比较；
- 返回并强制转换为整数的 8 个字段；
- 参数非法抛 `InvalidArgumentException`（400），球队不存在抛 `DomainException`（404），其他异常由控制器转为 500 且不泄露 SQL。

### 4.5 图表与 AJAX

- 饼图使用浏览器原生 Canvas 绘制，不引入第三方图表库。
- 初始渲染读取卡片 `data-*` 属性；切换下拉框时以 GET 请求 `/team/stats` 获取 JSON，仅更新对应卡片、饼图和标题。
- 使用 `AbortController` 与请求令牌：快速连续切换时，过期响应不会覆盖最新选择。
- 零场比赛显示空状态而不绘制空饼图；请求失败显示错误提示与“重试”按钮。

### 4.6 留言接入

- 比赛详情不再自行保存留言，改为挂载统一留言组件 `CommentWidget`，表单提交到统一的 `/comment/create`。
- 比赛目标的详情路由与存在性检查配置于 `frontend/config/params.php`；球队、球员目标采用同一套配置，留言组件同样挂载在球队、球员详情页。
- 待审核留言不在前台公开；提交成功 303 返回详情并提示审核后显示。

## 9. 认证与留言模块关键实现说明

### 9.1 留言目标解析

`CommentTarget::resolve($type, $id)` 仅接受 `team`、`player`、`match` 三种类型，按 `params.php` 中的配置检查目标是否存在：类型非法或配置未启用返回 404，配置缺失返回 503，未登录不可访问后台审核。每类目标对应 `team_id`、`player_id`、`match_id` 中恰好一个字段。

### 9.2 提交失败的返回方式与限流

- 表单只提交昵称和正文，目标由动作参数固定，避免篡改留言对象。
- 校验失败、触发限流或保存异常时，统一以 303 回到原详情页 `#comments`，错误挂在表单字段下，昵称和正文回填；不再渲染单独的失败页。
- 成功后写入 `pending` 并提示“审核通过后显示”，采用 POST→Redirect→GET 防止刷新重复提交。
- 同一会话保存成功时记录时间戳，60 秒内的后续提交只提示“提交过于频繁，请 N 秒后再试”，不写数据库。

### 9.3 审核状态机

允许的流转为：`pending` → `approved` / `rejected` / `deleted`；`approved` → `deleted`；`rejected` → `deleted`；`deleted` 无后续操作。界面按状态显示按钮，控制器在执行前再次校验，直接构造 POST 请求也会被拒绝。审核动作只接受 POST，并记录审核人和审核时间。

### 9.4 首页、后台首页与导航

- 前台首页显示主题横幅、6 支精选球队卡片与最近 5 场比赛（按北京日期倒序），未公布比分显示“未公布”。
- 后台首页统计球队、球员、教练、比赛、荣誉数量与待审核留言数，列出最近待审核留言并提供快捷入口。
- 后台导航分为基础资料（球队、球员、教练、阵容关系、执教关系、荣誉、球队荣誉）、比赛管理（场馆、比赛、球员统计）与留言管理。

### 9.5 关于本站与仓库入口

关于页展示项目定位、收录范围、主要功能、技术实现、课程作业仓库地址（新窗口打开）与小组成员。原模板 Contact 页面及其模型、测试、验证码动作一并删除，避免依赖未安装的 GD 扩展。

## 13. 基础资料模块关键实现说明

### 13.1 模型与唯一约束

- 阵容唯一性由模型 rules 配合数据库唯一键保证：同届球员仅归属一队（`player_id + tournament_year`），同队同届号码 1—26 唯一（`team_id + tournament_year + shirt_number`）；位置枚举 GK/DF/MF/FW。
- 球队 `fifa_code` 为 3 个字母且唯一；必填字符串 trim 后非空，简介、队徽、照片、出生日期可空为 NULL。
- 关系查询统一以 ID 关联（`hasMany`/`hasOne`），前台详情按 2026 届预加载阵容与教练，阵容按号码排序，不以姓名代替 ID。

### 13.2 详情页与挂载

- 球队/球员/教练详情对非法或缺失 ID 一律 404；缺图显示占位块，出生日期未知不显示年龄；全部输出经 `Html::encode` 转义。
- 球队、球员详情挂载统一留言组件（targetType=team/player），留言保存走统一提交处理器，基础资料与比赛模块不直接写审核字段。
- 球队详情战绩板块调用统一统计服务 `TeamStatsService::getSummary()`，服务异常时显示“暂时不可用”而不影响资料展示；同时提供“查看该队已收录比赛”（`FootballMatchSearch[team_id]` 筛选）与“与其他球队对比”（预选 `team_a_id`）入口。

### 13.3 后台维护与删除保护

- 七个后台控制器继承 `AdminController`，覆盖 behaviors 时保留 `parent::behaviors`；未登录访问统一 302 跳转登录。
- 删除前检查依赖引用，有关联记录拒绝删除并提示依赖，不做级联删除；被留言（含软删除）引用的资料同样不能直接删除。

### 13.4 素材补齐

按数据库样本为 6 支球队、24 名球员、6 名教练补齐 36 张图片至 `frontend/web/uploads/`，路径与 `logo_path`/`photo_path` 字段一致；媒体路径更新已并入 `data/install.sql`，来源记录见 `文档/媒体素材/`。

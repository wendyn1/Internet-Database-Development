# 跨模块接口约定

状态：本轮接口已由组长逐项确认，作为后续开发基线。仅完成设计，不代表接口已实现或联调通过；本步不修改业务代码、不创建表、不导入数据。

## 已确认：访问与详情路由

前后台独立应用沿用Yii默认URL，暂不启用地址重写。下表均为应用内部route，用Yii URL助手生成地址，不手工拼接宿主或端口。

| 前台对象 | 内部路由 | 参数 | 留言类型 |
| --- | --- | --- | --- |
| 球队详情 | /team/view | id，正整数 | team |
| 球员详情 | /player/view | id，正整数 | player |
| 比赛详情 | /football-match/view | id，正整数 | match |

示例：index.php?r=team%2Fview&id=1。访问不存在/非法ID返回404。所有录入的业务记录立即公开，留言publicExists只校验对应记录存在，不依赖发布状态。

已确认的详情路由尚未实现，留言配置暂不自动启用。待关联表及详情页就绪后，接入对应路由和真实记录存在检查。库外对手没有球队ID，只显示名称，不生成指向不存在球队的链接。

## 已确认：统一球队统计服务

球队详情、两队对比和胜平负饼图统一调用同一统计服务；不各写一套聚合，不保存冗余统计汇总表。具体方法、输出字段和图表请求方式已在下文固定。

输入为有效球队ID，首版赛事年份固定2026。统计只覆盖已录入、finished且双方比分完整的比赛，每场对该队只计一次。进失球按其主客位置计算；加时计入，点球大战不计入，点球决胜的平局仍计平。库外对手不要求有球队ID。

输出至少包含场次、胜、平、负、进球、失球。无有效比赛返回零场及零计数，图表显示空状态，不生成虚构占比。无效或不存在的球队ID不能当作有效球队的零场数据。

统计随数据库当前记录计算，首版不增加缓存；比赛更新后下一次请求反映最新结果。本说明不代表统计服务已经实现。

## 列表与对比接口（已确认）

以下为本轮确认方案的具体参数命名，统一使用GET；ID均为正整数，空字符串视为未筛选，数组或非法枚举不得直接传入SQL。

| 页面 | 路由 | 参数 | 固定排序 |
| --- | --- | --- | --- |
| 球队列表 | /team/index | name：中英文名称关键词；page | id ASC |
| 球员列表 | /player/index | name：中英文姓名关键词；team_id；position：GK/DF/MF/FW；page | id ASC |
| 比赛列表 | /football-match/index | team_id；date：YYYY-MM-DD北京时间日期；stage；status；page | match_date_beijing DESC, id DESC |
| 球队对比 | /team/compare | team_a_id；team_b_id | 按选择顺序左右展示 |

三种列表每页固定10条，page从1开始，不额外开放任意pageSize参数；翻页保留筛选条件。球员所属球队和位置以2026阵容记录判断。比赛球队筛选匹配任一侧库内球队ID，库外名称不当作ID。非法筛选在页面显示明确错误，不默默退回无筛选结果；正常筛选无结果显示空列表。查询使用Yii参数绑定，名称关键词不当作SQL片段。

对比未选择时展示表单；只选一队提示补全；选择同队、非法ID或不存在的球队时显示错误，不生成有效比较。两队无比赛仍可比较基本资料，进失球标注仅覆盖本站已录入且已结束的比赛，并显示零场/暂无比赛，不能当作完整赛事成绩。

## 统一统计服务与JSON接口（已确认）

下列代码落点、方法名及返回字段已确认，编码时按此实现；尚未编写或联调：

- common/services/TeamStatsService.php，方法 getSummary($teamId, $year = 2026)。首版仅接受2026；不存在球队与非法输入抛明确异常，不能伪装为零场。
- 返回字段：team_id、tournament_year、played、wins、draws、losses、goals_for、goals_against，均为整数。必须 played=wins+draws+losses。
- 服务每次根据有效比赛计算，不存冗余汇总；同一场不按球员统计行重复计数，也不把NULL比分补为0。
- 公开GET /team/stats?team_id=有效ID，Yii response format设置为JSON；前台切换球队时调用并局部重绘。

成功HTTP 200示意（仅结构示例，不是真实球队数据）：

```json
{"success":true,"data":{"team_id":1,"tournament_year":2026,"played":0,"wins":0,"draws":0,"losses":0,"goals_for":0,"goals_against":0},"message":"统计仅覆盖本站已录入的2026世界杯已结束比赛"}
```

无效参数HTTP 400，不存在球队404，数据库等服务异常500；JSON结构统一为success=false、data=null和不包含SQL/堆栈/凭据的message。线上调试模块需在部署阶段按环境关闭，本接口设计不宣称开发环境所有错误输出已经处理。

played=0时显示空状态，不画全零饼图；其他情况以wins/draws/losses作为饼图原始计数。异步加载显示加载状态，失败显示错误与重试入口；快速切换球队时取消前次请求或忽略过期响应，防止图表显示上一支球队的结果。


## 留言详情页提交契约（已确认）

| 接收动作 | GET | POST |
| --- | --- | --- |
| /team/view?id=球队ID | 球队资料与留言区 | 为该球队提交留言 |
| /player/view?id=球员ID | 球员资料与留言区 | 为该球员提交留言 |
| /football-match/view?id=比赛ID | 比赛资料与留言区 | 为该比赛提交留言 |

- 目标类型由对应详情控制器固定，目标ID取经校验的详情id；不从POST接收目标类型、其他对象ID、状态或审核字段。
- 统一接收CommentForm[nickname]、CommentForm[content]，保留CSRF验证。详情POST只处理留言，不处理球队/球员/比赛维护。
- GET显示空表单；POST失败在同一详情URL、同一详情视图重绘资料和留言区，将带错误及输入的CommentForm传给组件，响应422，不重定向丢失错误。未知对象404；保存失败用普通提示，不显示SQL。
- 保存成功后303重定向到同一详情GET的#comments，显示待审核提示；公开列表固定approved，不回显待审核记录。PRG不等于并发幂等。
- 复用frontend/widgets/CommentWidget.php，接口继续为targetType、targetId、model；model为空时新建表单，否则显示传入的表单及错误。每页10条，分页参数comment-page，与详情中其他分页参数分开。
- 后续将组件表单action从/comment/create改为经CommentTarget验证生成的固定详情地址。配置detailRoute分别为/team/view、/player/view、/football-match/view；publicExists查询对应业务记录存在，不查询发布状态，不允许无条件true。
- 组长提供frontend/components/CommentSubmission.php，建议统一方法submit($targetType,$targetId,CommentForm $form)：调用前由详情动作load表单；方法校验目标及表单并保存pending留言，成功true，失败false且给form添加错误；不得在组件run中保存、重定向或处理POST。
- B、C的详情动作仅负责加载资料、调用提交处理器、成功303/失败重绘及把form传入视图，不各写一套审核字段赋值和保存规则。

### 与现有代码的差异

现有CommentWidget仍提交到comment/create，当前CommentController在单独结果页显示错误，尚不满足本轮原详情重绘约定。后续编码应抽取统一提交处理器并切换表单action；旧comment/create不再作为正式提交入口，改为404，避免长期维护两套入口。旧接口的GET405仅是旧骨架检查结果，不代表最终接口验收。

本轮只记录该改造计划，不修改现有骨架，不提前配置回调开放留言。关联业务表及详情页就绪后，按此实施和联调。

## 后台共用接口（已确认）

所有业务控制器继承backend/controllers/AdminController.php，若覆盖behaviors必须合并parent::behaviors，不能丢失管理员过滤器。SiteController继续仅login/error公开；其他业务动作均要求当前指定的启用管理员，不能只检查“已登录”。

| 动作 | HTTP方法 | 行为 |
| --- | --- | --- |
| index/view | GET | 列表与详情，不写业务数据 |
| create/update | GET、POST | GET表单；POST校验保存，成功后重定向 |
| delete | POST | CSRF及依赖检查；有关联拒绝，无静默级联 |
| comment/review | POST | pending→approved/rejected；approved→deleted，非法状态流转拒绝 |

后台留言提供/comment/index、/comment/view、/comment/review，不开放通用delete。review输入id和status；目标状态只允许approved/rejected/deleted；服务端校验原状态并写入当前管理员、时间，不从表单接受审核人。index按status筛选，每页10条，created_at DESC、id DESC；id格式错误或记录不存在404，非法流转400，非POST405，CSRF失败400，成功303返回留言详情并提示。普通业务删除依赖冲突用清晰提示，不泄露数据库异常。
